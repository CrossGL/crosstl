## [3.9.0] - 2026-11-26

### Breaking Changes

- Without `--backend`, the single-file command refuses an output file name whose extension names no language CrossTL writes, such as `shader.spv`, `shader.txt` or `kernel.cl`, and lists the extensions it accepts. It used to write CrossGL into that file; pass `--backend cgl` for that.
- The target now chooses the GLSL profile. The `opengl` backend writes desktop GLSL, also from a GLSL ES source (WebGL 2 or OpenGL ES): a CrossGL `#version 100 es` or `300 es` line starts output at `#version 330 core`, and `310 es` or `320 es` at `#version 450 core`, which the generator raises as before. Desktop output leaves out GLSL ES `#extension` lines, starting from the desktop version that has the extension's constructs, and refuses an extension desktop GLSL has no form of, such as `GL_OES_EGL_image_external_essl3`. The new `gles` target (also `opengles` and `opengl-es`) writes GLSL ES for OpenGL ES 3.x: it keeps a GLSL ES `#version` line or starts at `#version 300 es`, leaves out a `GL_ARB_` line whose constructs GLSL ES has in its core language, and refuses one GLSL ES has no form of. WebGL output is still GLSL ES 3.00 and follows the same extension rule.
- Rust output writes rust-gpu kernels (`#![no_std]`, `spirv_std` 0.9 and `glam`) with `#[spirv(compute(threads(...)))]`, `#[spirv(vertex)]` and `#[spirv(fragment)]` entry points, instead of host Rust with `std` and `Vec` that rust-gpu rejected. What it cannot lower yet is refused with a `project.translate.rust-lowering-unsupported` diagnostic that names the construct (#4895).

### Added

- HLSL input imports the `out uint Status` overloads of the texture, storage-texture and typed-buffer reads as CrossGL `textureResidency` queries and `CheckAccessFullyMapped` as `textureResident`; both used to be refused. HLSL output writes a residency code as the read's own Status, so `textureResident` becomes `CheckAccessFullyMapped` again. A sampled texture's `Load(location, x)` with a `uint` `x` now imports as the offset overload DXC resolves it to, not as a Status read, and HLSL output writes `texelFetchOffset` on multisample textures as `Texture2DMS[Array].Load` instead of refusing it.
- GLSL, SPIR-V and HLSL output compute `exp`, `exp2`, `log`, `log2` and `pow` of `double` values, as CUDA, HIP and OpenCL C programs call them, with binary64 implementations written in CrossGL (from fdlibm, within one ulp). Those targets declare the functions for 32-bit floating point only: HLSL output used to compute them in single precision, GLSL output did not compile, and SPIR-V output refused them.
- The coverage report has a GLSL ES row, which measures the `gles` target's GLSL ES 3.x output. Its feature list is the GLSL ES 3.20 text of the GLSL specification source, the built-in functions and language-level features of OpenGL ES 3.2, and glslang checks each translation as the GLSL ES version it names. The nightly translation matrix measures translations into GLSL ES as well.
- The Coverage workflow publishes the page of each language to `languages/` on the `coverage` branch beside `COVERAGE.md`, so it is current after every measurement, and the README links to it. Each page now also lists the translation matrix cells the language is the source or target of, with their scores and a link to each cell's gaps.
- CrossGL has `gcd`, `lcm`, `factorial`, `comb` and `perm` for 8- to 64-bit integer scalars and vectors, with Mojo's and Python's meaning, and every target computes them exactly wherever the result fits the type.
- CrossGL `powi` and `powif` (a floating-point base to an `int` power, C17 F.10.4.4) now translate to Metal, HLSL, GLSL, SPIR-V, WGSL, Slang, Rust and Mojo through a declared CrossGL helper that multiplies by repeated squaring, per component for vectors; a binary16 base computes in binary32. Those targets refused the call, so HIP kernels calling `powif` or `powi` reached only CUDA and HIP. An integer base, a floating-point exponent or vector operands of different widths are refused with a typed diagnostic.
- CrossGL can write three texture operations other languages have (#4796). A depth comparison takes an optional level-of-detail bias as its last operand (`textureCompare(t[, s], P, ref[, bias])`, and the `Offset`, `Proj`, `ProjOffset`, `Clamp` and `OffsetClamp` forms), as HLSL's `SampleCmpBias` does. A depth-compare gather takes an optional component from 0 to 3 (`textureGatherCompare(t[, s], P, ref[, comp])` and its offset forms), as HLSL's `GatherCmpGreen`, `GatherCmpBlue` and `GatherCmpAlpha` do. `vec2 textureSamplePosition(t, int sample)` returns a multisample texture's sample position, which HLSL output writes as `GetSamplePosition`. A target whose generator does not lower one of them refuses it with `TextureOperandUnsupportedError`; a gather component of 0 is dropped, and one that is not an integer constant from 0 to 3 is refused with `TextureOperandError`. Generators declare support with `register_texture_operand_target`.
- CrossGL has a `node` stage for D3D12 work-graph node shaders (#4794). A `node { ... }` block holds one node: `@node_launch`, `@node_dispatch_grid`, `@node_max_dispatch_grid`, `@node_max_recursion_depth`, `@node_id`, `@node_share_input_of`, `@node_is_program_entry` and `@node_local_root_arguments_table_index` on the entry; HLSL's input record, output and output-records types with `@max_records`, `@max_records_shared_with`, `@node_array_size`, `@unbounded_sparse_nodes`, `@allow_sparse_nodes` and `@globallycoherent` on its parameters; `@node_track_rw_input_sharing` and `@ SV_DispatchGrid` on records; `GetRemainingRecursionLevels()` and `Barrier` with the Shader Model 6.8 flags. The shared passes refuse a node that breaks a rule DXC enforces under `lib_6_8` (launch mode, dispatch grid, thread group, input kind and count, system values per launch mode, `globallycoherent`, cross-group sharing, output-array attributes) with `WorkGraphNodeError`. Every target that has not registered node shaders with `register_work_graph_target` refuses the stage with `StageUnsupportedError`, and any other work-graph construct with `WorkGraphUnsupportedError`. CrossGL output keeps nodes as written.
- CrossGL has workgroup collectives: `workgroupAdd`, `workgroupMul`, `workgroupMin`, `workgroupMax`, `workgroupAnd`, `workgroupOr` and `workgroupXor` reduce a value over every invocation of the workgroup, their `workgroupInclusive*` and `workgroupExclusive*` forms scan it in local invocation index order, `workgroupAll` and `workgroupAny` vote, and `workgroupBroadcast(x, id)` returns invocation `id`'s value, as OpenCL C's `work_group_*` functions and MAX's `block` functions do. Every target computes them with a CrossGL helper that stores each invocation's value in a `shared` array between two workgroup barriers and combines the stored values, so all invocations receive the same result; calls in stages without workgroups, with an operand the helpers cannot take, or in kernels whose workgroup size the host chooses are refused.
- CrossGL has `workgroupUniformLoad(x)`, WGSL's read of workgroup memory that every invocation of the workgroup sees, for a `shared` variable declared at program or stage scope or an element or member of one. WGSL output keeps the call; every other target calls a helper that reads `x` between two workgroup barriers, as WGSL's polyfills do. CrossGL programs that called it were refused as calling an undeclared function.
- CUDA and HIP input translate `__syncthreads_count`, `__syncthreads_and` and `__syncthreads_or`. Each calls one CrossGL function that counts the predicate in a workgroup variable between barriers, so every target computes the block-wide vote; the importers refused the three votes before.
- CUDA and HIP input translate the intrinsics that round down, up or toward zero with a `float` or `double` result (`__fadd_rd`, `__dmul_ru`, `__fsqrt_rz`, `__fmaf_rd`, `__ddiv_ru`, `__int2float_rz`, `__ll2double_rd`, `__double2float_ru` and their siblings). Each call becomes a call of a CrossGL function, added to the imported program, that computes the exact IEEE 754 result in integer arithmetic, so the result does not depend on the target's division or square root accuracy, fused multiply-add or subnormal handling. They used to be refused. The directed conversions to `half` and `bfloat16` are still refused.
- CUDA and HIP input translate function templates into CrossGL generic functions, with their default type arguments, and calls with explicit template arguments into generic calls. Array extents written with integer constants, enumerators and constant expressions (`float tile[BLOCK * 2 + 1]`) are folded with C++ integer arithmetic, and an extent of a template value parameter (`float s[K * 2]`) is written as a CrossGL expression extent. An extent CrossGL cannot spell (a qualified name, a template-id, `sizeof`) or one that names a macro the program does not declare is refused with a typed diagnostic; the importers used to write it as an identifier that no program declares, which every target compiler rejected.
- CUDA and HIP output read CrossGL's `samplerBuffer`, `isamplerBuffer` and `usamplerBuffer` as texture objects bound to linear memory, and `texelFetch` on them as `tex1Dfetch`; they used to be refused (#4941).
- The documentation has a page per language, written from the published coverage report each time the documentation is built. Each page gives the score and counts of every direction, the reference tool and runtime the probes were checked with, the pinned feature lists, the measured features per category and the gaps grouped by cause.
- HLSL output writes CrossGL's debug print as HLSL's `printf` intrinsic, which DXC compiles to SPIR-V as `NonSemantic.DebugPrintf`; it used to be refused. DXIL has no print operation, so DXC still rejects the call when it compiles to DXIL.
- HLSL input and output carry the Shader Model 6.10 preview intrinsics `DebugBreak()` and `TriangleObjectPositions()` (with its `BuiltInTrianglePositions` result), which used to be refused as unknown calls. Every other target, Slang included, refuses them with a typed diagnostic.
- HLSL input imports `SampleCmpBias` as CrossGL's biased `textureCompare[Offset][Clamp]`, `GatherCmpGreen`, `GatherCmpBlue` and `GatherCmpAlpha` as `textureGatherCompare[Offset]` with the component, and `GetSamplePosition` on `RWTexture2DMS[Array]` as `textureSamplePosition`; each used to be refused. HLSL output writes the biased comparisons as `SampleCmpBias` (Shader Model 6.8) and the component gathers as `GatherCmp<Channel>`.
- HLSL output writes a CrossGL `node` stage as a `[Shader("node")]` entry of a Shader Model 6.8 library, with its launch, dispatch-grid, recursion, node-id, input-sharing and record attributes in their HLSL spelling, `globallycoherent` read-write input records and the thread-position system values the launch mode provides. HLSL input imports a `[Shader("node")]` entry as a CrossGL node stage with the same attributes, so HLSL work graphs round-trip (#4794).
- GLSL, SPIR-V and HLSL output compute `exp`, `exp2`, `log`, `log2` and `pow` of `double` operands with CrossGL helpers in binary64 arithmetic, since those targets declare the functions for 32-bit floats only. Before, the translation was refused.
- GLSL output writes CrossGL's `QuadAll` and `QuadAny` (HLSL's `QuadAll` and `QuadAny`, MSL's `quad_all` and `quad_any`) as `subgroupQuadAll` and `subgroupQuadAny` from `GL_EXT_shader_quad_control`; they used to be refused. A non-`bool` operand, and a quad vote under the software-subgroup lowering, are refused with a typed diagnostic (#4797).
- Metal input imports anonymous union and struct members of a class, such as the `union { struct { half d; half m; }; half2 dm; }` of the ggml quantized blocks: each is held by a member under a reserved name with the union layout contract, and accesses and methods that name a promoted member reach it through that member. Metal input used to refuse such a class. A `typedef struct { ... }` or `typedef union { ... }` now also declares the unnamed aggregates its members define; CrossGL output used to name them without declaring them.
- The metal-apple conformance harness binds Metal argument buffers of textures and samplers: a kernel argument that points to a structure whose members are all textures or samplers gets four elements filled with the resource IDs of their own textures and samplers. The Metal `unsized-array-of-textures` coverage probes, which used to end as harness errors, run on the Apple GPU in both Metal rows.
- Metal output translates GLSL's and SPIR-V's fragment shader interlock (`beginInvocationInterlockARB` and `endInvocationInterlockARB`): every buffer and image the critical section reaches, directly or through a called function, joins raster order group 0, and the calls are dropped. CrossGL's rasterizer-ordered view types are bound as their read-write views in raster order group 0. A subscript of a texture, which MSL has no operator for, is refused instead of emitted as written.
- Metal output writes GLSL and SPIR-V tessellation evaluation shaders as Metal post-tessellation vertex functions. Per-vertex input arrays and `gl_in[].gl_Position` become `patch_control_point` attributes, `patch in` variables the patch's other `[[attribute(n)]]` inputs, `gl_TessCoord` the `[[position_in_patch]]` input (`vec3(coord, 0.0)` in a quad patch) and `gl_PrimitiveID` `[[patch_id]]`. Without a tessellation control stage, which fixes the control-point count, the `[[patch]]` attribute takes the draw's count. Isolines, `point_mode` and reads of the tessellation levels are refused; Metal used to refuse every such stage.
- The metal-apple conformance harness binds the textures and samplers a Metal compute kernel declares (`[[texture(n)]]`, `[[sampler(n)]]`, arrays of textures and texture buffers): it creates deterministic float, half, int, uint, short and ushort texels for 1D, 1D array, 2D, 2D array, 3D, cube, cube array and buffer textures, and a nearest, repeating sampler with normalized coordinates, so the coverage texture and image probes execute on the Apple GPU instead of ending as harness errors. The Metal native texel-buffer and array-of-textures-nonuniform-index probes convert their input through `int` as the CrossGL probes do.
- Metal output writes a ray intersection stage that reports hits with `ReportHit` or `reportIntersectionEXT` as a Metal bounding-box intersection function that returns the closest hit it reports inside the ray's interval, and Metal input imports `[[intersection(bounding_box)]]` and `[[intersection(triangle)]]` functions as CrossGL intersection stages. Both used to be refused.
- Metal input imports intersection functions tagged `instancing`, `triangle_data`, `world_space_data`, `primitive_motion`, `instance_motion`, `extended_limits`, `curve_data` or `max_levels<N>`, and keeps `[[primitive_id]]`, `[[instance_id]]`, `[[front_facing]]` and `[[barycentric_coord]]` under their Metal names. Metal output writes the tags an intersection entry states plus the tags its inputs need, and accepts `[[user_instance_id]]`, `[[time]]`, and triangle `[[distance]]` and `[[front_facing]]` inputs.
- Metal input imports the quad-group functions: `quad_all` and `quad_any` as `QuadAll` and `QuadAny`, `quad_product`, `quad_min`, `quad_max`, `quad_and`, `quad_or` and `quad_xor` as clustered reductions of four lanes, and `quad_broadcast`, `quad_shuffle`, `quad_shuffle_xor`, `quad_shuffle_up`, `quad_shuffle_down` and the `quad_shuffle_rotate_*` functions as `QuadReadLaneAt` of the lane each reads (`QuadReadAcrossX`, `Y` and `Diagonal` for a constant xor of 1, 2 and 3). Other output languages used to receive the Metal names, which they do not define.
- Coverage checks the host interface of every Metal input round trip: the entry points of the Metal CrossTL writes back must keep the argument-table indices, argument-buffer layouts, vertex attributes, stage inputs and render targets of the native probe, read from the AIR metadata the Metal compiler writes (`tools/coverage/metal_reflection.py`). A render probe, which never runs, used to count as supported when its translation moved a binding.
- Mojo output writes CrossGL's `isnan`, `isinf`, `isfinite`, `nextafter`, `rcp`, `tgamma`, `nan`, `clz`, `ctz` and `mulhi` with the functions of Mojo's `std.math` and `std.bit`, and `atomicLoad` and `atomicStore` as `std.atomic`'s static `Atomic` load and store. An `if`, `else if`, loop condition or assignment target that increments, decrements or assigns, such as `while (k++ < n)` or `vals[k++] = x`, runs those side effects before its test or store instead of being refused.
- Mojo output lowers CrossGL's wave and subgroup operations: reductions, inclusive, exclusive, clustered and partitioned scans, votes, ballots and their bit counts, lane reads, shuffles, `WaveActiveAllEqual` and `WaveMatch` become helpers that loop over the active lanes of a MAX warp and read each lane with `shuffle_idx` under the active mask. `subgroupBarrier` is MAX's `syncwarp` between two fences, the `subgroupMemoryBarrier` family is a fence, and CUDA's `__match_any_sync` matches bit patterns within the caller's 32-lane CUDA warp. Quad operations are still refused.
- CrossGL has partitioned wave reductions and scans: `WaveMultiSum`, `WaveMultiProduct`, `WaveMultiMin`, `WaveMultiMax`, `WaveMultiBitAnd`, `WaveMultiBitOr`, `WaveMultiBitXor`, the inclusive `WaveMultiPrefixInclusive*` scans of each operator, and the exclusive `WaveMultiPrefixExclusiveMin` and `WaveMultiPrefixExclusiveMax`. GLSL input reads every GL_NV_shader_subgroup_partitioned function as one of them. Every target computes them with a loop over the subgroup's lanes built from `WaveActiveBallot`, `WaveReadLaneAt` and the lane index, so HLSL, Metal, GLSL, SPIR-V, CUDA, HIP, Slang and Rust output no longer refuse them.
- Rust output lowers CrossGL constant blocks (`cbuffer`) to rust-gpu uniform and push-constant parameters instead of refusing them: each block becomes a `#[repr(C)]` struct that places every member at the byte its std140, std430 (`@push_constant`) or declared `@buffer_layout` gives it, bound as `#[spirv(uniform, descriptor_set = S, binding = B)]` or `#[spirv(push_constant)]` on the entry points that read it, directly or through helpers. `bool` and `bvecN` members are held as `u32` words; std140 scalar, vector and `bool` arrays and 16-byte-strided matrices are held as 16-byte registers and rebuilt on read. A block member the struct cannot place, a whole-array read of a register array, an unsized array and a `bool` inside a struct are refused by name. Automatic resource bindings take the lowest free slot. A module-scope `@input` or `@output` variable the stage-interface passes leave behind is refused instead of read as a zero-valued static, and a read-only global whose default value is an array of vectors or matrices is a function, since a static cannot call `Default::default()`.
- Rust output lowers CrossGL textures, samplers and storage images to rust-gpu `spirv_std::Image!` and `Sampler` bindings instead of refusing them. Each image built-in calls the spirv-std method that issues the same SPIR-V instruction (`sample`, `sample_by_lod`, `sample_by_gradient`, the projective and `sample_depth_reference` forms, `gather`, `fetch_with_lod`, `query_size_lod`, `query_levels`, `query_samples`, `read`, `write`, `read_subpass`), and 1D-array images and texel buffers use inline SPIR-V. A combined sampler is split into an image and a sampler bound beside it, and helpers that sample it receive both. A storage image's format becomes part of its `Image!` type, so a helper parameter takes the format of the images its callers pass; loads from one-, two- and three-component formats are widened to four components as GLSL defines. Samples outside fragment shaders read the base level, as for SPIR-V, since rust-gpu rejects `ImplicitLod` instructions in compute and vertex entry points. Texel offsets, gathers with a depth reference or a non-constant component, storage images and helper parameters without a format, a helper parameter that receives images of two formats, multisampled storage reads and resource arrays of arrays are refused by name. The Rust coverage probes declare `StorageImageExtendedFormats`, as glslang does for GLSL.
- Rust output writes CrossGL atomics on storage buffers and workgroup memory as spirv_std atomics (`atomic_i_add`, `atomic_f_add`, `atomic_s_min`, `atomic_compare_exchange`, `atomic_load`, `atomic_store`, ...) at the Device or Workgroup scope, and lowers `cbrt`, `expm1`, `log1p`, `log10`, `rcp`, `copysign`, `signbit`, `pow` of a vector and a scalar, `determinant`, `inverse`, `refract`, `select`, `length_squared`, `distance_squared`, `absdiff`, `sincos`, GLSL's packing functions, `nan()`, `infinity()`, `epsilon()`, the subgroup barriers and `IsHelperLane()` to num-traits, glam and spirv_std calls. `cbrt` keeps C's sign for negative operands, which rust-gpu's `Float::cbrt` does not. Atomics on memory no other invocation shares, writes to read-only buffers and atomics SPIR-V lacks for the location's type are refused by name.
- Rust output lowers CrossGL's DXR inline ray queries to rust-gpu's `spirv_std::ray_tracing::RayQuery` instead of refusing them. A `RayQuery<FLAGS>` local (or the GLSL importer's `rayQueryEXT`) is declared with `ray_query!`, and `TraceRayInline`, `Proceed`, `Abort`, `CommitNonOpaqueTriangleHit` and the candidate and committed getters call the spirv-std method that issues the same SPV_KHR_ray_query instruction; the query type's flags are combined with the `initialize` flags as DXR combines them, and the ray flag and intersection kind constants are their values. An acceleration structure is a `&AccelerationStructure` binding, `RayDesc` a struct with DXR's fields, and `CommitProceduralPrimitiveHit` and the committed triangle's vertex positions, which spirv-std has no method for, are inline SPIR-V. The object-to-world and world-to-object matrices (glam has no 4x3 or 3x4 matrix) and queries that are parameters, struct members or module-scope variables are refused by name.
- Rust output writes CrossGL wave operations as rust-gpu's `spirv_std::arch` subgroup functions: reductions, inclusive and exclusive scans and clustered reductions by operand type (`subgroup_f_add`, `subgroup_s_min`, `subgroup_logical_xor`, `subgroup_clustered_u_max::<8, _>`, ...), votes, `subgroup_elect`, ballots and their bit counts, `subgroup_broadcast_first`, `subgroup_shuffle` and its xor/up/down forms, and quad broadcasts and swaps. `WaveGetLaneIndex()` and `WaveGetLaneCount()` bind the `subgroup_local_invocation_id` and `subgroup_size` built-ins, also in helpers. Rotations and partitioned operations are lowered through `subgroup_shuffle`. `WaveMatch`, the quad votes, HLSL's exclusive `WaveMultiPrefix*` forms and non-constant cluster sizes are refused by name.
- Slang output writes the C, MSL and GLSL built-ins that Slang's core module also declares (`copysign`, `fdim`, `fmax`, `fmin`, `nextafter`, `rint`, MSL's `fmax3`/`fmin3`/`fmedian3`/`max3`/`min3`/`median3`, GLSL's `bitfieldExtract`/`bitfieldInsert`, the `pack*` and `unpack*` functions, `interpolateAtCentroid` and `interpolateAtSample`) as those core functions instead of refusing them. Slang input imports the core module's `unpack*ToFloat`, `unpack*ToHalf`, `copysign_half`/`_float`/`_double`, `EvaluateAttributeAtCentroid`, `EvaluateAttributeAtSample`, and the 8-bit `packInt4x8`/`packUint4x8` (and their `Clamp` forms) and `unpackInt4x8To*`/`unpackUint4x8To*` functions as HLSL's `pack_*` and `unpack_*`. GLSL's `interpolateAtOffset` stays refused: `EvaluateAttributeSnapped` takes a different offset.
- Slang output binds `gl_ViewIndex` as `SV_ViewID`, `gl_ShadingRateEXT` and `gl_PrimitiveShadingRateEXT` as `SV_ShadingRate`, and an `int` `gl_FragStencilRefARB` as `SV_StencilRef`, refusing each in a stage, direction or type that lacks it. A fragment input structure's `gl_HelperInvocation` and subgroup members are read from `IsHelperLane()` and the `WaveGetLane*` functions in the entry body, as HLSL output already does.
- Slang input imports `InterlockedCompareExchangeFloatBitwise` and `InterlockedCompareStoreFloatBitwise` on a float buffer element or groupshared float as the HLSL importer does, so every target lowers them as it lowers the HLSL calls. The Slang importer used to refuse both.
- Slang input imports `RasterizerOrdered*` views as the HLSL importer does: the read-write resource with `@rasterizer_ordered`, whose subscripts become `imageLoad` and `imageStore`. The importer used to keep the subscripts of a rasterizer-ordered texture, which Metal and the other targets without texture subscripts cannot compile.
- Slang output writes the CrossGL shader clock built-ins with the reads Slang's core module declares: `clockARB()` and `clock2x32ARB()` keep their names, `clockRealtime2x32EXT()` becomes `getRealtimeClock()`, and `clockRealtimeEXT()` joins the two words of one `getRealtimeClock()` read in a helper. Before, the Slang generator refused all four. Slang input imports `getRealtimeClock()` and `getRealtimeClockLow()` as `clockRealtime2x32EXT()` and its `.x` component.
- Slang output writes CrossGL's `QuadAll`, `QuadAny`, `WaveActiveAllEqual`, `WaveActiveCountBits`, `WavePrefixCountBits`, `WavePrefixExclusive{Min,Max,BitAnd,BitOr,BitXor}`, the inclusive prefix scans, `WaveMultiPrefixCountBits` and the clustered reductions with Slang's core-module wave functions instead of refusing them; `bool` operands of the bitwise scans are scanned as `uint` 0 or 1. Slang input imports `WavePrefix{Min,Max,BitAnd,BitOr,BitXor}`, `WaveMultiPrefixExclusive*`, `WaveShuffle`, `WaveBroadcastLaneAt`, `WaveGetConvergedMulti`, `WaveGetActiveMulti`, the lane masks and the `WaveGetNumWaves`, `WaveGetWaveIndex`, `WorkgroupCount` and `WorkgroupSize` functions.
- The SPIR-V generator with `target_profile="vulkan-khr-cooperative-matrix"` lowers `cooperative_matrix_multiply_accumulate` (three and four arguments) to `OpCooperativeMatrixMulAddKHR`, `cooperative_matrix_add`, `_subtract`, `_elementwise_multiply` and `_negate` to the matching arithmetic instruction, `cooperative_matrix_fill` to `OpCompositeConstruct`, and zero-origin transposed loads and stores to `ColumnMajorKHR`. It also accepts storage-block member pointers such as `buf[0].a[k]` as transfer addresses. These used to be refused (#4709).
- SPIR-V output lowers `interpolateAtCentroid`, `interpolateAtSample` and `interpolateAtOffset` to the GLSL.std.450 interpolation instructions, reading the interpolant through the fragment input's own `Input` variable, including a member of an entry point's struct parameter, an element of an input array or a component of an input vector. An interpolant with no `Input` variable, such as a local value or a parameter the entry point writes, is refused.
- SPIR-V output reads a `QuadReadLaneAt` lane computed at run time, which it used to refuse. Each of the four quad lanes is read with `OpGroupNonUniformQuadBroadcast` and a constant index, and the lane `lane & 3` names is selected, as GLSL output does. HLSL `QuadReadLaneAt` and Metal `quad_broadcast`/`quad_shuffle` with a lane that differs per invocation now reach SPIR-V. A literal lane above 3 is still refused.
- CrossGL has subgroup rotations, `WaveRotate(value, delta)` and `WaveClusteredRotate(value, delta, clusterSize)`, with the semantics of SPIR-V `OpGroupNonUniformRotateKHR`. GLSL input reads GL_KHR_shader_subgroup_rotate's `subgroupRotate` and `subgroupClusteredRotate` as them, and GL_EXT_shader_quad_control's `subgroupQuadAll` and `subgroupQuadAny` as `QuadAll` and `QuadAny`. Every target reads the rotated lane with `WaveReadLaneAt` in a helper function per operation and operand type, so HLSL, Metal, GLSL, SPIR-V, CUDA, HIP, Slang and Rust output no longer refuse rotations.
- WebGL 2 shaders can be translated from: the source names `webgl`, `webgl2`, `essl` and `glsl-es` read GLSL ES 3.00 through the GLSL frontend, which keeps the `#version 300 es` line in the imported CrossGL (`crosstl.translate("shader.frag", backend="metal", source_backend="webgl")`). A `.webgl.glsl` file, the extension CrossTL writes WebGL output under, is read as source only when the source backend is named. The GLSL importer also keeps the block name of a uniform block that has no layout qualifier, as GLSL ES 3.00 blocks usually do; it used to name the CrossGL `cbuffer` after the block's instance, so the host could not find the block under its own name.
- WGSL output writes `gl_ClipDistance` and `SV_ClipDistance` vertex outputs as the `clip_distances` built-in, in a module that enables `clip_distances`. A `float` member is declared `array<f32, 1>` and accessed as its element 0, also in structure constructors; a `float[N]` member with N up to 8 keeps its type. Clip distances in a stage input, in another stage, of another type or in a second HLSL register are refused.

### Improved

- `crosstl shader.metal -o shader.hlsl` writes HLSL: without `--backend`, the single-file command takes the target from the output file's extension (`.hlsl`, `.metal`, `.glsl`, `.webgl.glsl`, `.spvasm`, `.wgsl`, `.cu`, `.hip`, `.slang`, `.rs`, `.mojo`, `.cgl`, and GLSL stage extensions such as `.frag` and `.comp`). - Coverage runs more compute probes on a GPU. Compute constructs that read no input, such as `local-invocation-id` and `subgroup-size`, now declare an unread input as function probes do, so the conformance harness runs them in the input and output rows.
- Coverage: the Metal output row compares the host interface (argument-table bindings, vertex attributes, stage inputs and outputs, render targets) that the Metal compiler records for each graphics probe's translation with the native Metal probe's, and reports a translation that changes it as wrong.
- Metal input translates corpus sources faster: the importer finds a source's concrete struct definitions once per source text, and sanitizes each template name once, instead of repeating both scans for every query. The output is byte-identical; on 154 corpus units the import takes 22 % less CPU time (#4846).
- Metal input to other targets spends less time preparing the source: the identifier and statement scans of template materialization skip characters they never act on, and each function body's statement scan runs once instead of once per declaration it is asked about. On eight slow corpus kernels the translation result is unchanged and CPU time drops by 7 % overall and by up to 27 % for one kernel (`rms_norm.metal` to GLSL).
- Metal input spends less time in two preprocessing scans, with unchanged output. The free-operator template scan stops each operator search at the end of the declaration instead of the end of the source and no longer copies the rest of the source for every `template <`. The temporary-functor check skips from one identifier to the next instead of stopping at every character.
- `crosstl.translate_artifacts` translates a file into the artifacts its target needs, importing the source once. When the target's compilation unit holds one entry point per stage (GLSL, GLSL ES) and the source declares two entries of one stage, it translates the discovered entries one artifact each from a single import, instead of importing the whole file only to learn its entries from the generator's refusal. The corpus worker uses it; on the Metal-source corpus slices this cuts GLSL translation CPU time by about a fifth.
- Translation takes less time, with byte-identical output: shared type queries and AST walks visit nested calls once instead of once per enclosing call (#4963, #4965), the initializer-scope renamer returns at once when no local needs a new name (#5000), and Metal input resolves the declared types of the names visible at an `auto` local only when it looks one up (#5001). HIP input translates graph runtime calls with one method per API family, and a SPIR-V module is reformatted, both without changing output (#4767, #4952).
- OpenGL output's software subgroups accept a strided loop that starts from a workgroup-uniform value plus the subgroup index, and a loop bound that a helper reading function constants computes, as MLX's `sdpa_vector.h` writes them (#5141).
- The Direct3D 12 runtime worker binds typed buffers, 1D, 2D, 3D and cube textures and their arrays, UAV counters and static samplers, so coverage runs HLSL probes that declare them on WARP instead of reporting harness errors (#5088).

- Slang output now writes GLSL and SPIR-V ray tracing stages in the form Slang declares: the payload, hit attributes and callable data become `static` variables that the entry point receives as parameters and copies back, `TraceRay` takes a `RayDesc` and the payload, `CallShader` the callable data and `ReportHit` the hit attributes. slangc rejected the module-scope interface variables CrossTL wrote before (a non-`static` global is a uniform) and `ReportHit` without its attribute argument; `ReportHit(t, kind)` without a hit attribute variable now reports placeholder attributes of the type the hit stages declare. CrossGL ray stages without such variables keep their Slang forms. What has no DXR form, such as `gl_ObjectToWorldEXT`, is refused for Slang.
- Slang input writes the `POSITION`, `NORMAL`, `TANGENT` and `BINORMAL` semantics (and their index 0) as `Position`, `Normal`, `Tangent` and `Binormal`, the names the HLSL importer writes, so a Slang vertex input takes the semantic's fixed location as the same HLSL input does, and a geometry input array such as `line float4 position[2] : POSITION` gets a GLSL location.
- Slang input imports more declarations: a `for` initializer that declares several variables (`int i = 0, n = 4`) writes the type once, a C-style `typedef` of an array type is kept, a struct whose name is a CrossGL keyword is renamed everywhere it is used, and a generic function keeps its generic parameters and their interface constraints (`<T : IFloat & IArithmetic>`, `__generic<...>`, `let N : int`). Variadic (`each T`) and defaulted generic parameters are refused by name. Slang output of a push-constant `ConstantBuffer<T>` whose `T` places its members with `@offset` at std430-aligned offsets now writes them as `[[vk::offset]]` instead of refusing them; `@align` is still refused.
- Slang input keeps 8- and 16-bit integer arithmetic at the width Slang computes it: `int8_t v = 13; float(v * v)` imports as `float(int8_t(v * v))`, so the round trip computes Slang's -87 instead of the promoted 169. Operands of mixed signedness convert to their common narrow type, and the right operand of `/=` and `%=` on a narrow scalar converts to the scalar's type, as slangc does.
- Slang input keeps geometry, hull and domain entry points: a geometry stage's input primitive (`triangle float4 p[3]`), `[maxvertexcount]` and `[instance]`, the hull stage's `[domain]`, `[partitioning]`, `[outputtopology]`, `[outputcontrolpoints]`, `[patchconstantfunc]` and `[maxtessfactor]`, the domain stage's `[domain]`, the `SV_GSInstanceID`, `SV_OutputControlPointID`, `SV_TessFactor`, `SV_InsideTessFactor` and `SV_DomainLocation` values and the patch constant function's `InputPatch` parameter. Before, they were dropped and the translated stages were refused when written back as Slang.
- Slang input keeps nested block and braced `case` scopes, the parentheses of nested prefix operators (`-(-x)`), member functions, enumerator scopes (`E::A`), `packoffset` and `[[vk::offset]]` member placements, `[earlydepthstencil]`, the conservative depth semantics and `[[vk::shader_record]]` constant buffers, and no longer writes a prototype as an empty function. Each of these compiled differently after a Slang round trip. A generic member function and a shader record that is not a constant buffer are refused. Slang output declares a texture passed to a separately sampled parameter as a separate texture, and writes a component `packoffset` register.
- Slang output promotes 8- and 16-bit integer scalar operands to `int` when the source does (CrossGL, Metal, CUDA, HIP and OpenCL C), as C's integer promotion requires: `int8_t v = 12; float(v * v)` is 144 again rather than Slang's 8-bit -112. A promoted result stored into a narrow scalar is converted explicitly, and `/=`, `%=`, `<<=` and `>>=` on a narrow scalar compute on the promoted value. Sources without promotion (GLSL, HLSL, SPIR-V, Slang) keep Slang's narrow arithmetic.
- Slang output now reads the subgroup built-ins from Slang's wave intrinsics (`WaveGetLaneCount()`, `WaveGetLaneIndex()`, the `WaveGetLane*Mask()` masks, and `WaveGetNumWaves()`/`WaveGetWaveIndex()` in compute-class stages), writes `select` with the condition first (and the Slang importer writes it back in CrossGL order), declares `gl_PointSize` as `SV_PointSize`, writes `layout(early_fragment_tests)` as `[earlydepthstencil]`, selects `SV_DepthGreaterEqual`/`SV_DepthLessEqual` for conservative depth layouts, declares rasterizer-ordered buffers and images with the `RasterizerOrdered*` types, and keeps an `hlsl_cbuffer` constant buffer's HLSL offsets with `packoffset` (refusing a member HLSL packs inside std140 padding).
- Slang output declares a function parameter that receives a `@rasterizer_ordered` resource, directly or through another function, with the `RasterizerOrdered*` type, and writes an explicit `@rasterizer_ordered` parameter that way instead of as a semantic. slangc rejected the `RW*` parameter the call passed the ordered view to (E30019). A parameter that receives both an ordered and a plain resource is refused.
- Slang output now writes a one-matrix constructor that changes the matrix's shape through a helper that keeps the upper-left elements and fills the rest from the identity, swizzles a wider vector argument of a vector constructor to the target's width, writes `b.length()` of a structured buffer as its element count, declares a scalar `gl_CullDistance` member as a one-element array (slangc writes a scalar one as a non-array `CullDistance` built-in, which the Vulkan specification forbids), and writes `MaybeReorderThread` as Slang's `ReorderThread`.
- Slang output accepts a ray payload, hit attribute or callable data of a scalar, vector, matrix or array type, such as the `int` attribute of `ReportHit(t, kind, attribute)`, which it used to refuse. Slang wraps such a value in a structure itself when it compiles for Direct3D.
- Slang output refuses a recursive call cycle, which slangc rejects for every GPU target (error E55201), with the `RecursionUnsupportedError` SPIR-V, WGSL and Metal output raise, and writes a function whose self calls are tail calls as a loop. Slang output declares a shader record buffer as a `[[vk::shader_record]] ConstantBuffer<T, L>` in the record's std430, std140 or scalar layout, and Slang input reads the layout argument back. SPIR-V, GLSL and Slang output refuse a shader record that a stage other than a ray tracing stage reads (VUID-StandaloneSpirv-ShaderRecordBufferKHR-07119).
- Slang output no longer types a wave operation's operands with the type its result is assigned to, so a `uint` lane index inside `WaveReadLaneAt` on a `float4` value translates. A domain stage's `@partitioning` and `@outputtopology` are validated and omitted, since Slang takes them from the hull, and `SV_DomainLocation` is `float2` on quad and isoline domains.
- DirectX and OpenGL software subgroups accept a loop whose bound, start or stride is a constant that a conditional expression selects, such as `constexpr short limit = wide ? 16 : 8;` after a Metal template argument fixes `wide`. The condition must be a literal, a known constant, or a comparison or `!`, `&&`, `||` of checked integer constants, and only the selected operand is evaluated. Such a loop around a barrier or a subgroup collective used to be refused as not statically uniform.
- SPIR-V output honours a CrossGL compute, mesh or task stage's `layout(derivative_group_quadsKHR) in;` or `layout(derivative_group_linearKHR) in;` (the NV spellings too): it declares `DerivativeGroupQuadsKHR` or `DerivativeGroupLinearKHR`, which form the quads of the stage's derivatives and quad operations, and refuses a workgroup the group cannot divide. A declared group takes precedence over the group derived for derivatives, and a stage with quad operations and no layout keeps subgroup quads (#4840). SPIR-V input imports the two execution modes as these layouts. Before, a stage that declared 2x2 quads read subgroup quads in `QuadReadAcrossY` on lavapipe, and an 8x8 stage that declared the linear group and took derivatives declared the 2x2 group.
- SPIR-V output writes an unsuffixed float literal in a `double` context, such as `x * 0.1` with a `double` `x` or `double d = 0.1;`, as the `OpConstant %double` of its decimal value; it used to write the binary32 constant and widen it with `OpFConvert`, so `0.1` became `0.10000000149011612`. A literal with an `f` suffix keeps its binary32 value. Built-in calls that mix `float` and `double` operands, such as `max(0.9, x)` or `mix(a, b, t)`, now take the `double` overload as GLSL overload resolution does, instead of narrowing the `double` operands to `float`.
- SPIR-V assembly import treats functions named `main` as ordinary helpers unless they are declared in `OpEntryPoint`. The importer renames those helpers and their calls so they do not collide with the GLSL entry point (#4600).
- SPIR-V input renames a parameter or local that shares its name with a function of the module, such as glslang's `float twice;` in a shader that also calls `twice()`. C-family scoping let the local hide the function, so the GLSL, HLSL and Metal translations were rejected.
- SPIR-V input imports `OpBeginInvocationInterlockEXT` and `OpEndInvocationInterlockEXT` as CrossGL's `beginInvocationInterlockARB()` and `endInvocationInterlockARB()`, and the four interlock execution modes as `layout(pixel_interlock_ordered) in;` and its sample and unordered forms; both instructions used to be refused. Device and image reads are no longer moved into or out of the critical section, and a read of a `Uniform` `BufferBlock` buffer is evaluated before a later store to that buffer instead of after it.
- SPIR-V input keeps a block member's `RowMajor` decoration as CrossGL `@row_major` on struct members and on uniform and storage block fields, and writes square matrices as `matN` and `dmatN`, so the matrix layout passes see them; the import used to read row-major matrices as column-major (#2959). A nested prefix operator is parenthesized, so `-(-x)` no longer imports as the decrement `--x`. SPIR-V output decorates `Patch` for CrossGL `@patch` varyings as well as the `patch` qualifier (#3946), and lowers `fmin` and `fmax` to GLSL.std.450 `NMin` and `NMax` behind the NaN guard instead of `FMin` and `FMax`, whose result is undefined for a NaN operand.
- SPIR-V input keeps 8- and 16-bit integer arithmetic at its width: a narrow scalar `OpIAdd`, `OpISub`, `OpIMul`, `OpShiftLeftLogical`, `OpSNegate` or unsigned `OpNot` imports as `i8(...)`, `u16(...)` and so on, because CrossGL promotes narrow scalars to `int` before arithmetic. `OpBitcast` between 8-, 16- or 64-bit integers of one width now imports as a constructor instead of being refused. The subgroup vote, ballot, shuffle, quad, rotate and partition instructions now import as the GLSL subgroup functions (the quad votes as `QuadAll` and `QuadAny`) instead of failing on an unknown value, and SPIR-V output writes `QuadAll` and `QuadAny` with SPV_KHR_quad_control.
- SPIR-V input declares the truncated remainder of an `OpSMod`, and its divisor unless that is a variable or literal, as locals where the instruction is defined. The sign correction reads them four and three times, so an `OpSMod` whose operand was itself an inlined `OpSMod`, such as `(a + b % 2) % 2`, repeated the inner one four times per level and grew exponentially with the nesting depth; the imported expression is now a tree that grows linearly.
- SPIR-V output keeps the ordering of rasterizer-ordered resources (`RasterizerOrderedBuffer`, `RasterizerOrderedTexture2D`, CrossGL `@rasterizer_ordered`): the fragment entry point declares `PixelInterlockOrderedEXT` with SPV_EXT_fragment_shader_interlock and brackets its body with `OpBeginInvocationInterlockEXT` and `OpEndInvocationInterlockEXT`, as DXC does (#4306). Explicit `beginInvocationInterlockARB()` and `endInvocationInterlockARB()` calls are lowered, and the fragment stage's interlock layout picks the execution mode. A fragment entry point that returns early is refused. SPIR-V output also writes conservative depth layouts (`@depth_greater`, `@depth_less`, `@depth_unchanged`) as `DepthGreater`, `DepthLess` and `DepthUnchanged` execution modes, and SPIR-V input reads them back (#3597, #3600). A depth layout on an output other than the fragment depth is refused.
- SPIR-V output increments and decrements a by-value scalar parameter (`x++`) and a member of an `inout` structure parameter (`s.c++`, `++s.c`). It wrote `OpLoad` of the parameter's value for the first, which spirv-val rejects, and refused the second.
- SPIR-V input imports `OpPtrAccessChain` and `OpInBoundsPtrAccessChain` by adding their `Element` operand to the index of the array element the base pointer names, so `&a[i]` moved by `e` reads `a[i + e]`. Before, `Element` became one more subscript and the CrossGL no longer type-checked. A pointer that does not name an array element, or whose `ArrayStride` differs from its array's, is refused. A struct whose `OpName` is a built-in type name, such as the `RWStructuredBuffer` block slangc writes, is declared as `RWStructuredBuffer_` instead of shadowing the built-in type. SPIR-V output accepts the GLSL declaration `int gl_SampleMask[1]` as a fragment output. SPIR-V output also lowers `p - n` on a buffer pointer and re-binds a pointer local with `q = p`, `q = q + n` or `q = q - n` when the new value points into the same buffer, by updating the pointer's element offset; a pointer re-bound to another buffer is refused.
- WGSL output gathers a module's stage-level `@input` and `@output` variables, such as those the SPIR-V importer declares for a vertex or fragment shader, into the entry point's parameters and result instead of declaring them `var<private>`, so the shader reads its inputs and writes its outputs. SPIR-V's unnamed blocks (`__0`) are written as valid WGSL identifiers, and GLSL's `int gl_SampleMaskIn[1]` is received as the `u32` `sample_mask`. Slang output no longer declares a compute stage's built-in inputs that the entry point binds as globals, which Slang made an implicit uniform parameter block.
- SPIR-V output of a tessellation evaluation stage that reads the patch constants as a structure, as HLSL domain shaders and Metal post-tessellation vertex functions do, now validates. A narrower tessellation level member (`float edges[3] : SV_TessFactor`, `float inside : SV_InsideTessFactor`) reads the leading elements of the `TessLevelOuter`/`TessLevelInner` built-ins, which spirv-val used to reject as a mismatched constituent type; a per-patch member is a `Patch` input placed after the control-point inputs, where SPIR-V output of the tessellation control stage writes it, instead of a refused location conflict; and Metal's `[[position_in_patch]]` is the `TessCoord` built-in.
- SPIR-V, WGSL and Slang output now lower a union's `uchar4` byte view (`union { uint2 val; uchar4 bytes[2]; }`) to the bytes of its storage words, reading each `u8vec4` as one word and writing one lane or a whole vector into it. Narrow-integer legalization keeps a union's members at their declared width, so such a union is no longer refused as an `ivec4[2]` view that does not match its two words.
- SPIR-V, WGSL and Slang output keep the shared storage of a struct with the union layout contract, which the CUDA, HIP and Metal importers write for a C union, so a program that writes one member and reads another reads the bytes it stored. They declared one member per view (#4782).
- WGSL output writes `f16tof32(f32tof16(v))` as `quantizeToF16(v)`, which rounds to binary16 on every driver, and Slang output reads an element of `gl_HitTriangleVertexPositionsEXT` as `HitTriangleVertexPosition(index)`, which slangc declares, and refuses the whole array (#4782).
- HLSL, GLSL and SPIR-V output lower a union member narrower than the union's storage (a struct of 8-, 16- or 32-bit scalars, a narrow vector, or a scalar or vector that covers only part of the storage) to one lane array per element type over the whole storage, and rewrite member reads and writes to lane accesses. Taking such a member's address, incrementing it, compound assignment to it and swizzle writes to it are refused with `UnionWordViewError` instead of being emitted with the wrong layout.
- A storage buffer that SPIR-V declares but the entry point never reads, whose block ends in a runtime array, now translates: its block struct is rewritten like a used one's instead of being declared with an unsized member that every target refused.
- WebGL 2 output now reports an unsupported lowering diagnostic naming the wave or quad intrinsic, barrier, or built-in variable when a shader needs subgroup operations. The GLSL importer renames user functions whose names CrossGL reserves for these intrinsics, for example `subgroupAdd` to `subgroupAdd_` (#4843).
- WGSL output declares the bound parameters of a CrossGL compute entry (`@group(g) @binding(b) var<storage> p: array<T>`) as module-scope bindings and reads its plain-value parameters, such as an imported CUDA kernel's `int n`, from a `<entry>_Args` uniform block at the first free binding. It wrote them as entry-point parameters, which naga rejects, and copied a storage buffer passed to an `out` parameter into a function variable of runtime size.
- WGSL output refuses offset lookups on cube textures — `textureOffset`, `textureLodOffset` and `textureGradOffset` on a `samplerCube`, and `textureCompareOffset` and `textureCompareLodOffset` on a `samplerCubeShadow` — with `WGSLCubeTextureOffsetUnsupportedError`, as it already did for cube array textures. It used to write the offset into the `textureSample*` call, which naga rejects (`Sample offset constant ... doesn't match the image dimension Cube`) (#3550).
- WGSL output writes barriers in helper functions that only compute entry points reach, directly or through other helpers, which it used to refuse. Such a helper is written in the compute stage's context, so its implicit-LOD texture lookups also sample level 0 as the entry point's own lookups do. A barrier in a helper that a vertex or fragment entry point also reaches is still refused, because WGSL rejects it.
- WGSL output translates the NaN-avoiding `fmin`, `fmax`, `fmin3` and `fmax3` that Metal, CUDA (`fminf`, `fmaxf`) and HIP kernels call. WGSL declares none of them, so the generator refused those kernels; each call is now a helper per operand type that tests both operands' binary32 bits and returns the one that is not a NaN, as SPIR-V's `NMin` and `NMax` do. Integer or double operands stay refused.
- WGSL output writes a constructor of an array of arrays, such as `float[2][3](float[3](...), float[3](...))`, as nested WGSL array value constructors (`array<array<f32, 3>, 2>(...)`); it used to copy the outer constructor as written, which WGSL compilers reject. A workgroup dimension set through `local_size_x_id = N` names the program's own specialization constant of id `N` in `@workgroup_size` instead of declaring a second override of the same id.
- WGSL output reads a uniform block at the offsets its declared layout gives (std140 by default, std430 for push constants, or `@buffer_layout`), where WGSL's own uniform layout differs: `mat2` and other two-row matrices, row-major matrices, HLSL `cbuffer` packing and std430 scalar arrays. Such a block is declared as `array<vec4<T>, N>` registers and each member is read from its register; the output used to declare the typed members, so it read other bytes than the host wrote.
- WGSL output declares a buffer pointer's array `array<atomic<T>>` when atomic built-ins address its elements, reads an `int` stage input bound to `vertex_index`, `instance_index` or `sample_index` through `i32()`, writes GLSL's subgroup built-in inputs as WGSL's, and follows GLSL's conversions: matrix resizes such as `mat3(m2)`, `int` and `uint` operands of float operators, swizzle writes such as `c.ga = v`, and `bvec` uniform members (#4771).

## [3.8.0] - 2026-11-20

The [full 3.8.0 notes](https://github.com/CrossGL/crosstl/blob/0beb48b8bde7d3b6c50dbd2926c968c87bc19cc4/CHANGELOG.md#380---2026-11-20) describe each of the release's 69 changes.

### Breaking Changes

- Every refusal has its own diagnostic class, and the last places that wrote an unsupported construct through, or put a comment, a zero or an empty block in its place, refuse it instead. Name lookups in every generator and importer are exact, so an unknown stage, semantic, built-in, operator or type is refused.
- CUDA and HIP input refuse directed-rounding intrinsics such as `__fadd_rd`, which used to round to nearest, and device-side runtime calls such as `cudaMalloc` and kernel launches, which used to become comments.
- CUDA and HIP output refuse vertex, fragment, geometry, tessellation, mesh, task and ray-tracing entries, since a kernel is their only entry point.
- GLSL output refuses a program with two entries of one stage. Translate each entry with `entry_point=` or `crosstl.translate_entries` instead.
- WGSL, Rust and Mojo output refuse a `@precise` function, since they cannot forbid fused multiply-adds, and Mojo output refuses wave operations.
- Metal input expands `STEEL_CONST`, `C10_METAL_CONSTEXPR`, `mittens_DEFAULT_ALIGN` and `c10::metal::array` from the project headers that define them instead of recognizing the names, so without those headers they are a syntax error.

### Added

- `crosstl.translate_entries` translates several entry points of one source, each to its own artifact, and project translation splits a GLSL unit with two entries of one stage into one artifact per entry.

### Improved

- Translating large programs, Metal ones most, takes less CPU time, with byte-identical output.
- The Metal importer reads more template-heavy MSL, including static member calls through member aliases, reference aliases bound through local receivers and integral-constant arithmetic over block-scope constants.
- GLSL output's software subgroups accept a loop or helper that leaves on a subgroup reduction of a value every lane computes alike.

### Fixed

- 58 fixes, mainly to WGSL, SPIR-V, Metal, CUDA and HIP output and to CUDA, HIP, OpenCL C, Metal and HLSL input. Many keep the floating-point semantics of CUDA, HIP and OpenCL C programs, such as IEEE arithmetic, no contraction, the rounding of halfway cases and the accuracy of `sin`, `cos` and `pow`; others concern integer and float conversions in WGSL output, warp and subgroup operations, workgroup sizes, storage buffers and pointers, shadow textures and the shader clock built-ins.

## [3.7.0] - 2026-11-13

The [full 3.7.0 notes](https://github.com/CrossGL/crosstl/blob/8283636516c5a1b66c43bcf6c384c7ee5e0610fd/CHANGELOG.md#370---2026-11-13) describe each of the release's 117 changes.

### Breaking Changes

- Every target refuses a function body that reads or writes a name it never declares, with `UndeclaredIdentifierError`, and a call to a function that neither the program nor any language CrossTL reads declares, with `UndeclaredFunctionError`. Both used to be copied into the output.
- GLSL, HLSL and Metal output refuse what they have no spelling for instead of writing it unchanged, such as built-in types and functions of other languages and, in GLSL output, members, semantics and functions nothing declares. GLSL, SPIR-V, HLSL and Metal output refuse an HLSL system value they do not know.
- A storage image format CrossGL does not know is refused with `UnsupportedImageFormatError`.
- Metal and Slang output refuse a constant-buffer member that `@offset` or `@align` places where their declaration would not, with `MemberPlacementError`, and HLSL and GLSL output refuse such placements in the structure of a `ConstantBuffer<T>` that declares no layout. HLSL input refuses a `[[vk::push_constant]]` struct whose DXC layout CrossGL cannot record.
- A helper's `buffer T name[]` parameter takes the form of the buffer its caller passes, and one whose elements have no common stride across std430, HLSL structured buffers and MSL is refused with `StorageBufferParameterUnsupportedError`. HLSL, GLSL, SPIR-V and Slang output used to write an unsized array parameter that their compilers reject.
- The CrossGL output of a Metal, GLSL, HLSL or SPIR-V import starts with `#pragma cgl_rules(...)`, which names the semantic rules of the source language, so the saved CrossGL translates the same as the source.

### Added

- HLSL input translates function and struct templates, including template value parameters, to CrossGL generics, and resolves namespaces by C++ lookup rules.
- CrossGL generic functions take value parameters, as in `generic<T, N>` called as `scale<float, 3>(x)`, and generic structures such as `Box<float>` translate to SPIR-V as well as the other targets.
- Storage images take the packed formats `rgb10_a2`, `rgb10_a2ui` and `r11f_g11f_b10f`.
- Metal input keeps a declaration-only function template that explicit specializations complete.

### Improved

- The Metal importer reads more template-heavy MSL, including member templates selected by a library tag, default template arguments of deduced calls and body-local aliases of dependent types.
- More MLX kernels translate to DirectX and OpenGL. OpenGL output proves index bounds from the comparisons that guard a read, and DirectX and OpenGL output write through 32-bit storage word views.
- Translating large programs to HLSL is faster, with unchanged output.

### Fixed

- 97 fixes, mainly to Metal, Slang, HLSL, SPIR-V and GLSL output and to Metal and HLSL input. Many concern the layout of constant buffers, push-constant blocks and storage buffers, arrays and `inout` arguments passed to functions, matrix order, memory qualifiers, and tessellation and workgroup sizes.

## [3.6.0] - 2026-11-08

The [full 3.6.0 notes](https://github.com/CrossGL/crosstl/blob/v3.6.0/CHANGELOG.md#360---2026-11-08) describe each of the release's 238 changes.

### Breaking Changes

- Output refuses a specialization constant it cannot keep specializable, where it used to freeze the constant at its default value.
- The CrossGL parser refuses a token it cannot place, and a malformed `generic<...>` declaration, with a `SyntaxError` that names the construct. It used to skip them.
- The Metal, HLSL and Vulkan GLSL importers refuse a statement or expression they cannot import (`MetalImportRefused`, `DirectXImportRefused`, `SpirvStatementUnsupportedError`) instead of writing a comment in its place.
- `static_assert` is checked for every target: a false condition is refused with `StaticAssertionFailedError`, and one the translator cannot evaluate with `StaticAssertionUnresolvedError`.
- HLSL and Slang input import `SV_VertexID` as `gl_RelativeVertexID`, which leaves out the base vertex as Direct3D does. GLSL, SPIR-V and Metal output read it as `gl_VertexIndex - gl_BaseVertex`.
- HLSL output refuses `volatile` and system-coherent resources, and a call that passes two private pointer views of one local array when either is writable. SPIR-V output refuses `coherent(system)` and `coherent(host)`.

### Added

- A compute, mesh or task entry whose threadgroup size the host chooses at dispatch time, such as a Metal kernel that reads `threads_per_threadgroup`, translates to SPIR-V, GLSL, WGSL, HLSL and Slang. The size comes from specialization constants or WGSL overrides, or from `CROSSGL_WORKGROUP_SIZE_X`, `_Y` and `_Z` macros that the host defines when it compiles the shader.
- HLSL output reads a specialization constant without a default from a `CROSSGL_SPECIALIZE_<name>` macro.
- `@explicit_specialization(primary, types)` replaces the body of a generic function for the given type arguments.
- GLSL and Metal output lower HLSL `ByteAddressBuffer` and `RWByteAddressBuffer`, including signed `InterlockedMin` and `InterlockedMax`.
- SPIR-V output lowers `atomicLoad` and `atomicStore`, and the GLSL importer reads `GL_KHR_memory_scope_semantics` atomics.
- Geometry stages that write several vertex streams translate between GLSL, HLSL and SPIR-V.
- `local_size_x_id`, `local_size_y_id` and `local_size_z_id` make a workgroup dimension a specialization constant on SPIR-V, GLSL, Slang and WGSL output.
- Cooperative matrices gain `cooperative_matrix_diagonal(value)` and independent component types for a multiply-accumulate, and Metal `simdgroup_matrix` kernels that do not use `thread_elements()` lower to GLSL and HLSL.
- The HLSL, Metal, CUDA, HIP, OpenCL and Slang preprocessors define `__COUNTER__`, `__INCLUDE_LEVEL__`, `__BASE_FILE__` and, except for HLSL, `__FILE_NAME__`.

### Improved

- The Metal importer reads more of the template-heavy MSL in MLX, PyTorch and ggml kernels, including constrained templates, `enable_if` overload selection, `decltype` return types and type traits in constraints.
- Importing and translating large Metal sources is faster.
- WGSL output passes array elements, structure members, vector components and module-scope variables to `inout` and `out` parameters through temporaries.
- Slang output lowers the wave shuffle functions that Metal's `simd_shuffle_*` functions import as.
- Refusals that depend only on a program's entry stages or workgroup sizes are reported earlier.

### Fixed

- 184 fixes, mainly to Metal input and to WGSL, Metal, GLSL and HLSL output.

## [3.5.0] - 2026-10-30

The [full 3.5.0 notes](https://github.com/CrossGL/crosstl/blob/v3.5.0/CHANGELOG.md#350---2026-10-30) describe each of the release's 291 changes.

### Breaking Changes

- Vertex inputs and varyings take their location from one rule on GLSL, SPIR-V, WGSL and Metal: an explicit location, then the classic semantic table (`POSITION` 0, `TEXCOORD0` 5, `COLOR0` 13 and so on), then the first free location. Host vertex layouts written for the old numbers need updating.
- A storage buffer without `@buffer_layout` holds its elements at std430 offsets on Metal and HLSL, as on the other targets. `buffer T name[]` declares one storage buffer of `T` for every `T`, structures included.
- Metal output samples a combined sampler, such as GLSL `sampler2D`, through a `sampler <texture>Sampler [[sampler(n)]]` argument that the host must bind. It used to sample through a fixed inline sampler.
- CrossGL refuses non-square `floatNxM` and `doubleNxM` spellings (`AmbiguousMatrixSpellingError`), undeclared type names, and `gl_` attributes that name no built-in or are used where GLSL does not declare them. `(a, b)` is the C comma operator. `sizeof` folds to a constant on Metal, HLSL and GLSL and is refused for operands it cannot size.
- CUDA and HIP output refuse a construct they cannot lower with `CudaLoweringRefused` or `HipLoweringRefused`. They used to write a comment and a placeholder value in its place.
- Target limits are refused with typed errors: derivatives in compute, mesh, task and ray generation stages on Metal, 64-bit integers, doubles and bfloat16 on WGSL, constant buffers over 64 KiB on HLSL, and `WaveSize`, mesh, amplification and ray-tracing stages on the `dx10` and `dx11` profiles.
- Importers refuse constructs they cannot translate faithfully: Metal `sinpi` and its family, ray-tracing functions, indirect command buffers and rasterization rate maps, GLSL `tensorARM` uniforms, sampler feedback textures and OpenCL C device-side enqueue events.
- Mojo output declares constants with `comptime` instead of `alias`, and refuses a vector where a scalar is expected.

### Added

- `crosstl doctor` lists, for each backend, the validation tools CrossTL looks for and which of them are on `PATH`.
- GLSL mesh and task shaders (`GL_EXT_mesh_shader`) translate to HLSL and Metal, and Metal `[[mesh]]` and `[[object]]` functions import as mesh and task stages.
- CrossGL structures may declare member functions, and CrossGL, GLSL, HLSL, Slang and CUDA input accept a structure declared in a function body.
- Sparse texture residency queries translate to GLSL, Metal, HLSL and SPIR-V, and the GLSL importer reads `GL_ARB_sparse_texture2` and `GL_ARB_sparse_texture_clamp`.
- `gl_InstanceIndex` translates to OpenGL, OpenGL ES, HLSL and SPIR-V. Metal `constexpr sampler` state translates to OpenGL through host sampler objects.
- `metal_sizeof(x)` measures a type with Metal's layout rules. The SPIR-V importer reads subpass inputs.
- GLSL output reads a specialization constant without a default from a `CROSSGL_SPECIALIZE_<name>` macro.
- Project translation for DirectX and OpenGL flattens a compute workgroup whose shape the target cannot declare but whose thread count it can, and a project can declare read-only entry storage immutable with `immutable_storage`.

### Improved

- The Metal importer reads more of the MSL in real headers and MLX kernels: template argument deduction, partial specializations, `decltype`, `conditional_t` and the `<simd/simd.h>` aliases.
- WGSL output monomorphizes generic functions and passes `inout` and `out` parameters as pointers.
- Inline ray queries have one CrossGL spelling, the DXR method names, and translate between HLSL, GLSL and SPIR-V.
- Metal argument table indices become SPIR-V bindings, and fixed sampler state becomes host samplers on Direct3D and Vulkan.
- SPIR-V output folds module-scope constant expressions exactly in binary32, HLSL and GLSL output write the float limits such as `FLT_MAX` exactly, and Metal `half` matrices keep binary16 values on SPIR-V and WGSL.
- Arrays of HLSL structured buffers keep their tight element layout on GLSL, SPIR-V and Metal.
- Translating large sources is faster.

### Fixed

- 226 fixes, mainly to CUDA, HIP, WGSL, Metal, HLSL and Slang output.

## [3.4.0] - 2026-10-23

### Breaking Changes

- CrossTL requires Python 3.11 or later. Python 3.8, 3.9 and 3.10 have reached end of life and are no longer supported.
- CrossGL syntax can change between releases until CrossGL expresses everything its targets can. In this release, debug prints are `printf(format, values...)` instead of `debugPrintfEXT`, comparison samplers have their own `comparison_sampler` type, and HLSL and Metal textures import as separate textures and samplers.
- A Metal, CUDA, HIP or OpenCL kernel whose results depend on a threadgroup size that the host picks at dispatch is refused for HLSL, GLSL, SPIR-V and WGSL output, which used to fix the size at 1, 1, 1. Pass the dispatch size as `source_options={"threadgroup_size": (x, y, z)}` or in a project workgroup-size rule.
- A CrossGL function body that does not parse is refused; it used to become an empty block. An untyped `var` whose type cannot be inferred from its initializer, or that has no initializer, is refused instead of being declared `float`.
- CrossGL `matCxR` has GLSL's column-by-row meaning on every target, and HLSL `floatRxC` imports as `matCxR`. Comparison operators and `!` are componentwise on vectors, as in HLSL, MSL, WGSL and SPIR-V. Ray payload access qualifiers are `@ray_payload_read(...)` and `@ray_payload_write(...)`.
- The Metal, OpenGL, WebGL, DirectX, SPIR-V, Slang and Rust generators, and the HLSL and Metal importers, refuse a construct they cannot translate with a typed error that lists every such construct, such as `MetalLoweringRefused` or `SpirvLoweringRefused`. They used to write an `/* unsupported */` or `; WARNING` comment next to a neutral value and return a program that ran differently.
- SPIR-V output from HLSL takes descriptor sets and bindings from `register(Xn, spaceM)` and `[[vk::binding]]` instead of numbering resources in declaration order, and refuses two resources on one register. OpenGL output gives each descriptor set or register space small per-class binding points instead of `set * 1024`.

### Added

- A coverage report. CI translates a probe for every feature in each language's pinned upstream feature list, checks the result with that language's reference compiler or validator, and publishes the scores and every gap to [COVERAGE.md](https://github.com/CrossGL/crosstl/blob/coverage/COVERAGE.md).
- Texel buffers (`Buffer<T>`, `RWBuffer<T>`, `samplerBuffer`, `imageBuffer`) translate between HLSL, GLSL, Metal and SPIR-V.
- DXR ray-tracing stages lower to Vulkan SPIR-V and GLSL, with hit attributes, ray payloads and callable data. HLSL output marks ray payloads with `[raypayload]` and their access qualifiers.
- Shader debug prints translate to SPIR-V and Metal.
- GLSL geometry stages translate to HLSL's stream form.
- Non-uniform resource indices translate to GLSL, Metal and GLSL ES.
- HLSL structured-buffer counters (`IncrementCounter` and `DecrementCounter`) work on Metal, GLSL, CUDA and HIP through an explicit counter buffer.
- Built-in values can be written in their GLSL, HLSL or WGSL spelling in CrossGL and translate to every target.
- Untyped `var name = expr;` declarations, including in `for` loop initializers and at shader scope, take their type from the initializer.
- HLSL geometry, hull and domain stages translate to GLSL and SPIR-V. Metal, which has no geometry or tessellation stages, refuses them with a typed error.
- GLSL subgroup built-ins, including the prefix, clustered and ballot forms, translate to SPIR-V, HLSL and Metal.
- Source arithmetic profiles for binary32 addition, subtraction, multiplication, division, remainder, precise arctangent and logarithms. DirectX, OpenGL and Metal output get native controls for rounding, subnormals, signed zeros and non-finite values.
- Thread-grid dispatch regions, fixed partial workgroups, Boolean subgroup votes and software subgroup products. Unsupported collective control flow is reported as an error.
- Native runtime support for Boolean, binary16, bfloat16, byte and 64-bit integer storage, shared allocation views and immutable DirectX constants.
- Checked integer metadata preconditions carried through project artifacts, reflection and runtime packages.
- MLX integration demos for array creation, copies, casts, reductions, indexing, scatter and random generation through translated runtime packages.
- Package metadata lives in `pyproject.toml` with a pinned Flit build backend. Releases install the wheel and the source distribution in isolation and verify the published PyPI archives before the GitHub release is created.

### Improved

- Every supported Python version, 3.11 through 3.15, is tested.
- Unsized HLSL resource arrays get their size on Metal and OpenGL from bounded dynamic indexes as well as constant ones, so translated shaders no longer read past the array.
- HLSL texture samples return the texture's element type, and storage-image loads and stores use four-component texels as GLSL defines them.
- CUDA and HIP buffer elements such as `float3` and structs with vector members keep their host layout on every target.
- SPIR-V modules for mesh, task and ray-tracing stages, which need SPIR-V 1.4, declare storage buffers in the `StorageBuffer` storage class and pass `spirv-val`.
- GLSL stage inputs and outputs are named so the stages link, and never redeclare a global.
- Metal import and graphics code generation are faster on large kernels.
- Buffer layouts carry across targets: HLSL structured, append and consume buffers, Metal packed and natural layouts, and GLSL std140, std430 and scalar blocks keep their offsets. HLSL `row_major`, `packoffset` and `pack_matrix` are honoured, and `GetDimensions` reports the element stride on GLSL, SPIR-V, CUDA and HIP.
- Texture sampling keeps its meaning across targets, including LOD clamps, implicit LOD outside fragment stages, projected depth comparisons, Metal array layers and explicit sampler pairs.
- OpenGL output declares the lowest GLSL or GLSL ES `#version` that provides every construct the program uses.
- Stage interfaces translate more faithfully: GLSL interface blocks keep their member locations, struct-typed varyings are flattened for SPIR-V and split for Metal, a GLSL fragment shader's several outputs become one HLSL or MSL structure, and each SPIR-V entry point has its own interface locations.
- `SV_ClipDistanceN` and `SV_CullDistanceN` keep their index, and GLSL and SPIR-V pack them into one distance array in DXC's order.
- Arrays of uniform blocks bind one buffer per element, Metal `constant` matrix parameters bind as HLSL constant buffers, and SPIR-V bindings of Metal resource parameters follow MSL's separate buffer, texture and sampler indices.
- The SPIR-V importer rebuilds structured control flow, keeps integer signedness, extended arithmetic and `NoContraction`, and imports arrays of storage blocks.
- The Metal importer handles more real-world sources: `__METAL_VERSION__` and `__METAL__` are predefined, shared headers that use `<simd/simd.h>` types translate without Apple's SDK headers, and kernels with 16-bit thread-index attributes, `unsigned int` template arguments, `::metal::`-qualified SFINAE constraints or type traits in explicit instantiations translate.
- A function whose recursive calls are all tail calls is translated as a loop instead of being refused.
- Native Metal dispatches reuse a long-lived worker process instead of starting one per dispatch.
- Precise Metal square root, logarithm, power and `atan2` keep signed zeros, special values and underflow behaviour under explicit operand profiles.
- HLSL, GLSL and Metal output keep integer promotions, vector initialization, byte narrowing, binary16 selection, bfloat rounding, atomic destinations and argument evaluation order.
- Source maps no longer guess line locations. Only artifacts that preserve lines carry line mappings.
- MLX project files moved to `demos/integrations/mlx`.

### Fixed

- The parser no longer hangs on an unterminated shader declaration, and parses `if`, `else` and loop bodies without braces.
- HLSL output renames GLSL and Metal identifiers that HLSL reads as keywords, such as `line`, `point`, `vector` and `Buffer`.
- Metal SIMD-group and quad-group functions declared behind `METAL_MAYBE_UNDEF` are recognized.
- SPIR-V output keeps the source semantics of signed remainder, `fmod`, signed right shifts, mixed-sign arithmetic and NaN tests, copies locals initialised from buffer elements, and passes loose uniforms in a `CrossGLDefaultUniforms` block instead of private variables the host cannot set.
- HLSL output stores the written components of a GLSL buffer-block vector; it used to assign to a load, which DXC rejects.
- HLSL output declares vertex, instance, primitive and sample indices as `uint`, as DXIL requires.
- GLSL output rebuilds a flattened stage-input structure used as a whole value, and guarded multi-stage GLSL declares one `main` per stage.
- Functions that share a name with a module-scope value are renamed in HLSL, GLSL and MSL output, and constants that read struct constants are declared after the structs.
- HLSL `SubpassInput` keeps its type through CrossGL, and `gl_PointCoord` reaches Metal as `[[point_coord]]`. OpenGL refuses input attachments and HLSL refuses `gl_PointCoord`.
- Metal sparse texture reads, colour-attachment inputs on targets without framebuffer reads and array literals passed to Metal array parameters are refused with a typed error instead of producing code that does not compile. WebGL refusals are typed as well.
- Metal colour-attachment outputs can be any scalar or vector of up to four components, and casts after `return` import correctly.
- GLSL mesh built-in arrays and named `case` labels translate to SPIR-V.
- Project metadata requirements apply only to the source entry that declares them.
- Unreferenced out-of-line Metal call operators no longer block kernel translation.
- DirectX compilation resolves relative includes through long Windows paths.
- Software subgroup lane reads, shuffle-and-fill and guarded inputs keep their semantics in HLSL and GLSL output. Metal output uses shuffles for dynamic lane indices.
- HLSL scalar-to-vector construction evaluates increment and decrement operands once.

## [3.3.0] - 2026-10-01

### Added
