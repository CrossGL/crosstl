CUDA and HIP input now give each surface the storage-image format of the element type its accesses read and write (`float` -> `r32f`, `uint2` -> `rg32ui`, `uchar4` -> `rgba8ui`, with `iimage`/`uimage` for integer elements), import the pointer form `surf2Dread(&v, s, x, y)` as an assignment of the texel, take the leading components of the texel a read returns, and divide every x byte offset by `sizeof(T)` structurally, in CUDA as in HIP. The pointer form was copied verbatim and the format was lost, so the surface reached Metal, GLSL, HLSL and SPIR-V as an undeclared call or as a four-component float image. A surface accessed as two element types, or as a 64-bit or three-component type, is refused. CUDA and HIP output read and write 8- and 16-bit integer image formats (`r8ui`, `rgba16i`) instead of refusing them, and storage-image parameters lowered from CUDA keep their format into HLSL, SPIR-V and Metal. A namespace-scope `__device__ cudaSurfaceObject_t` handle and a surface reference (`surface<void, 2> s;`) import as the bound image they are, with that format, instead of a storage buffer holding an image.
