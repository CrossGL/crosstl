HIP input writes each named union as a CrossGL struct with the union layout contract (`@union_layout(size, alignment, little_endian, hip)` and `@union_member_layout(0, size, alignment)` on each member), as CUDA input does. A HIP program that writes one member of a union and reads another, copies a union, passes one to a function or reaches one through a pointer now imports instead of being refused, and the word-based targets keep the shared storage. A union whose layout the importer cannot describe (bit-fields, member alignment specifiers, `packed`, anonymous struct members, pointer members, `double4`) is refused with a reason that names it.
