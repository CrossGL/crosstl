CUDA and HIP output read and write a storage image through surface elements of its format: `float` for `r32f`, `uchar4` for `rgba8`, the bits of `__half` values for `rgba16f`, or the type an `@texel` attribute names. They used to read and write every float image as `float4`, so a surface access of an `r32f`, `rgba8` or `rgba16f` image read or wrote 16 bytes at the wrong byte offset. A load now widens the element to the four components `imageLoad` returns and converts unorm, snorm and half channels to floats, and a store converts the value back. A load that initializes or is assigned to a scalar or a narrower vector reads only those components, and a stored scalar is splatted. 8- and 16-bit integer formats and packed formats are refused with a diagnostic.
