WGSL output writes valid WGSL for constructs that HLSL, Metal, GLSL, CUDA and SPIR-V sources translated straight to WGSL got wrong: bit casts of vectors named `float3`, implicit conversions between vectors of different element types (`uint2 r = countbits(i)`, `int2 r = sign(f)`) and between `bool` and numbers, `Texture1D.SampleGrad` (as `textureSampleLevel` at the gradients' level), NaN and infinity bit constants (made at run time, since a const-expression NaN is a WGSL error), `T a[N] = {}`, Metal entry textures and samplers (now module bindings), Metal vertex entries returning a bare `float4` (the position), Metal `atomic_compare_exchange_weak_explicit`, and GLSL reads of `gl_FrontFacing`, `gl_SampleID`, `gl_PrimitiveID`, `gl_VertexID` and `gl_InstanceID`.
