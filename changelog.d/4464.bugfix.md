Fix Vulkan API version negotiation and SPIR-V module version validation.

- `VulkanComputeRuntime._create_instance` now calls `vkEnumerateInstanceVersion`
  when available and requests Vulkan 1.1 when the loader supports it, falling back
  to Vulkan 1.0 otherwise (fixes the root bug where `VK_API_VERSION_1_1` was absent
  from the Python `vulkan` binding).
- `_VulkanDispatchContext._create_shader_module` now validates the SPIR-V module
  version against the effective device API version (the lower of the requested
  instance version and `VkPhysicalDeviceProperties.apiVersion`) before calling
  `vkCreateShaderModule`, raising a typed `RuntimeAdapterSetupError` with
  `reasonKind: spirv-version-incompatible` on mismatch.
- The three SPIR-V helper functions (`_spirv_module_version`,
  `_vulkan_spirv_ceiling`, `_validate_vulkan_spirv_module_version`) are now
  correctly placed at module level after `_vk_destroy`, fixing the
  `IndentationError` that prevented `import crosstl.project`.
