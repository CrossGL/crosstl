Metal, WGSL, Slang and GLSL output now choose between matrices with a conditional instead of `select(...)`, which their compilers reject: `select(m1, m0, c)` becomes `c ? m0 : m1` on Metal, Slang and GLSL, and an `if`/`else` on the whole initializer or assignment on WGSL (a matrix `select` anywhere else is refused, as a matrix ternary already is). The lowered conditional is parenthesized, so an operator next to the call cannot bind to one branch only; a matrix `select` whose operand is multiplied by a vector takes the `mul(...)` form on Slang; and a value argument with a side effect refuses on every backend, since the conditional would skip the branch the condition does not pick while `select` evaluates both. HLSL and SPIR-V output are unchanged (#4525).
