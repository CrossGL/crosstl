Metal input deduces a function template's arguments from a struct template argument that spells a defaulted argument, as in `tile_add(P, Q)` with `Tile<float, 1, 1, Frag<float, 8, 8>> P` and a parameter `thread Tile<T, M, N>&`, and from one that omits it when the parameter spells it. The call used to bind another specialization, and translation to GLSL, HLSL and other targets that instantiate templates failed. A call such as `F::add(d, a)` whose qualifier depends on a template parameter of a function template that stays generic is now refused; it used to lose its qualifier and call whatever unqualified `add` the program declared. A function template that nothing instantiates is left out instead, as its constrained overloads are.
