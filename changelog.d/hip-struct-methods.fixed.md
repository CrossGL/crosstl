HIP input lowers the member functions a kernel calls to CrossGL free functions that take the receiver first (`Span_width(Span this_)`, with an `inout` receiver when the function writes a data member), through the CUDA importer's struct-method pass, so HIP and CUDA import the same source to the same CrossGL. HIP input used to refuse every member-function call. Calls of static, virtual, template, declared-only and reference-returning member functions, and of member functions of record templates and derived records, are still refused, and a member call with template arguments such as `s.as<float>()` no longer reaches the output as the text of a parser node. The CUDA pass also accepts `while` loops in member function bodies.
