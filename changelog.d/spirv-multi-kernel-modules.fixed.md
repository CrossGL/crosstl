SPIR-V output writes a CUDA or OpenCL C file with several kernels as one module with an entry point per kernel. Every kernel binds its own parameters from binding 0, which was refused as "Duplicate SPIR-V resource binding"; resources of different kernels may now share a descriptor slot, identical parameters of several kernels are one variable, a parameter another kernel declares differently gets its own, and each kernel reads its own `<kernel>_Args` members. CUDA helper functions that take pointers (`__device__ float get(const float* a, int i)`) are bound to the buffer, offset or `__shared__` array they receive instead of being refused as "Unknown type ptr<f32>".
